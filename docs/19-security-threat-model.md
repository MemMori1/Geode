# 19 — 安全威胁模型（信任边界 / 攻击面 / TH-01~TH-22 / 漏洞响应）

> 本文**拥有**：信任边界、不可信输入分级、攻击面登记、TH-01~TH-22 威胁清单、防线机制库、漏洞响应流程、安全默认值，以及"安全谁负责哪一段"的分工边界。
> 本文**不拥有**：各子系统实现细节（见 02/04/06/07/10/11/12/13/14/15/16/17）、验证手段与语料（见 20）、性能门槛（见 21）、法务条款（见 18 §13）。
> 上游契约：`见 00 §5`（核心类型）、`§5.3`（`Layer`）、`§7`（性能预算）、`§9`（全局原则，尤其第 4 条"默认安全"）、`§12`（错误码登记表）。
> 许可假设（不在本文展开）：程序本体 MIT OR Apache-2.0，模板/主题资源库 CC0-1.0，文档 CC BY 4.0，插件任意许可而 ABI 头文件 MIT。**其安全含义只有一句**：许可证挡不住他人分发恶意内容，只能靠签名与安装期校验（15 §4.3、TH-16）。
> 本文沿用 00 §10 的十节骨架；每节标题下用一行说明本节承载的威胁模型内容，便于与 20/21 对齐。

**读者与用法**：写 PR 的人看 §3 + §5（这是审查清单，不是背景阅读）；值班处理漏洞的人看 §6；想加新功能的人看 §2 + §4（先判断有没有引入新信任边界）。

## 0 决策速览

1. **"打开攻击者构造的文件"是常态功能，不是异常场景**。默认值一律朝拒绝/只读/可关闭倾斜，不提供"一键全放开"（§8）。
2. **只承认三条真隔离线**：OS 进程边界、FFI/C 库边界、网络边界。同进程内的预算、配额、`catch_unwind` 只是**把"必然失败"降级成"可用"**，不是安全边界；文档与 UI 文案必须与此一致（14 §7.3 已诚实声明）。
3. **v1 的真实 RCE 面只有两处**：插件（被引入的任意代码）与 C 依赖（Capstone）。其余不可信输入的最坏后果是 **DoS 或数据损坏**，投入按此分级，不平均用力。
4. **一切"声明尺寸"只用于拒绝，不用于分配**。`with_capacity(header.n)`、`alloc(w*h)` 形式的代码在 PR 中直接打回（§5 铁律 C）。
5. **内容与规则先验签后用**：模板/主题/magic/YARA/插件走同一验证序（15 §4.3 ①→⑥）；`allow_unsigned=false` 是发行默认且**不可被项目文件覆盖**，只能由用户在本机改。
6. **破坏性与外发型动作一律独立二次同意**：写块设备、写进程内存、AI 上云、安装插件、开 `permissive`。**"记住上次选择"被否决**（06 §4.4）。
7. **可复现构建是安全响应的前置条件**：没有可复现产物就无法证明补丁有效（§6）。

## 1 目标与非目标

### 1.1 目标

| # | 目标 | 判据 |
|---|---|---|
| S1 | 一份**可执行的**信任边界与攻击面清单，覆盖每个外部输入进入系统的位置 | §2.2 图 + §3.2 表无空缺入口 |
| S2 | 每条威胁都有编号、影响类别、现有防线（可追溯到文档节）、残余风险、等级 | §4.2 的 22 条逐一可查 |
| S3 | 每条威胁都能映射到一个验证手段（由 20 落地） | §9.1 与 §7.1 双向对齐 |
| S4 | 安全默认值成表，且每项写清"打开后失去什么" | §8 |
| S5 | 外部研究者能在 10 分钟内知道怎么报漏洞、多久能听到回音 | §6.3 |
| S6 | 新功能设计时能回答"它引入了哪条新信任边界" | §3.2 可直接增量扩展 |

### 1.2 非目标（明确不做，不接受以"顺手"为理由扩张）

| # | 非目标 | 理由 |
|---|---|---|
| N1 | **不做 EDR / 终端防护**：不监控进程行为、不做持久化检测、不扫描宿主 | 我们是分析工具不是安全产品；越界会带来"承诺了没做到"的责任 |
| N2 | **不做沙箱逃逸对抗**：不假设攻击者在与我们对抗（无 ASLR 绕过、无 Spectre 缓解、无侧信道加固） | 防的是"文件把人搞崩/搞脏"，不是靶场对手。成本与形态不成比例 |
| N3 | **不做 DRM / 反拷贝 / 许可证强制执行** | 开源双许可无从谈起；且与"用户拥有自己的数据"直接冲突 |
| N4 | **不做反调试 / 反虚拟机 / 反分析** | 我们**是**分析工具；任何反分析能力都会被用来对付我们自己的用户 |
| N5 | **不做系统级沙箱**（seccomp / AppContainer） | v1 无此工程量；真实隔离是进程隔离（14 §10 Q5），属 v2 |
| N6 | **不做加密容器破解或绕过** | 超出产品边界 |
| N7 | **不写合规清单**（ISO/SOC2/等保） | 本文是工程文档；需要时另起合规映射，不在此堆条文 |

**边界模糊处的裁决规则**：只有"防御专业攻击者"才能满足的需求 → 归 N2，不排期；能防住"随手构造的恶意样本"的 → 归 S1~S6，必做。

### 2.2 信任边界图

四条边界标为 `B1`~`B4`。**跨过一条边界 = 输入从"数据"变成"能影响代码执行的东西"**，这是所有分级判断的起点。

```
  文件字节/项目文件/内容包/.geoplug/剪贴板/字体（U1~U10，§2.3）
        │
        ▼            ╔══════════════════════════════════════════════════╗
  ┌──────────────┐   ║ B1  OS 进程边界（单进程，持有用户的全部权限）      ║
  │ 攻击者可控输入 │──►║  ┌──────────┐      ┌────────────────────┐        ║
  └──────────────┘   ║  │ geode-ui │      │ geode-plugin-host  │        ║
                     ║  └────┬─────┘      └─────────┬──────────┘        ║
                     ║  ┌────▼──────────────────────▼─┐  │ B2          ║
                     ║  │ core / buffer / bspec / proc │  │（反向调用）  ║
                     ║  │ search / diff / disasm /     │  │             ║
                     ║  │ yara / analysis / viz        │  │             ║
                     ║  └──┬──────────────────┬────────┘  │             ║
                     ╚═════│══════════════════│═══════════│═════════════╝
                        B2 │                  │ B3        ▼
        ┌──────────────────▼───┐  ┌───────────▼───────┐  ┌───────────────────┐
        │ libcapstone (C, FFI) │  │ 远程数据源         │  │ .geoplug (cdylib) │
        │ 段错误/UB 不可 unwind │  │ SSH/SFTP / GDB-RSP│  │ 第三方代码，       │
        └──────────────────────┘  │ HTTP 索引          │  │ 同地址空间同权限   │
                                  └──────────┬────────┘  └───────────────────┘
        ┌──────────────────────────────────────▼─────────┐
        │ B4 AI / 云端边界：采样切片 → 远端模型（出向）     │
        │ 远端返回 → 模板/建议（U9，须先过 Verifier）       │
        └────────────────────────────────────────────────┘
```

**读图要点**：`B2` 有**两个**跨越点——Capstone（我们调 C）与插件（C 反向调我们），后者更危险，因为它把攻击者写的代码放进你的地址空间，而前者只是数据被 C 代码误解。`B3` 上"服务端不可信"：SFTP 可以撒谎（返回 `../../../`、伪造大小），GDB stub 可发畸形 RSP 包。`B4` 是**出向**边界，风险不是"被攻击"而是"我们主动把取证数据送出去"（TH-15）。`B1` 之内没有隔离，这条事实决定了 TH-12/TH-13 的等级只能是"降级"而非"消除"。

### 2.3 不可信输入分级（10 类）

| ID | 输入 | 入口 | 最坏后果 | 主要防线 |
|---|---|---|---|---|
| U1 | **被打开的文件字节** | 本地/块设备/进程内存/远程 Provider | 解析器崩溃、OOB 读、DoS | 02 §7.2 预算；04 附录 A.1；06 §3.1 短读铁律 |
| U2 | `.bspec` 模板（含 AI 生成的） | 手工打开、内容库、项目文件、AI 输出 | 预算耗尽、越界读、把用户引向错误结论 | 02 §7.2；15 §4.9；03 Verifier |
| U3 | 插件 `.geoplug` | 用户目录、内容库 | **RCE（等价于用户自己运行它）**、进程崩溃 | 14 §3.3 能力模型、§4.1 验签、§4.4 子进程预检 |
| U4 | 内容包 `.geopkg` | 内容库/镜像/内网 | 路径穿越、炸弹、投毒模板 | 15 §4.3 验证序、§4.9 内容安全 |
| U5 | `.gmagic` 规则 | 内容库、`magic.library_paths` | 匹配期 CPU/内存爆炸、误导格式判定 | 10 §6 指令与窗口上限；15 §4.9 |
| U6 | `.geoproj` / `.geows`（同事发来的） | 双击、最近文件 | 指向任意路径或主机、伪造 `secret_ref`、布局注入 | 17 §3.4/§4.2/§4.4。**同族还有 `.geopatch`（任意偏移改写）与 `.geojournal`（回放覆盖数据）** |
| U7 | 主题与字体文件 | 内容库、`config.ui.font_*` | 解析器 0day、显存耗尽、界面不可读 | 16 §4.7 实测等宽、§6 回退内置 |
| U8 | 远程数据源（SSH/SFTP/GDB/HTTP 索引） | 地址栏输入 | 明文凭据、host key 替换（中间人）、服务端撒谎 | 06 §4.6 RSP 仅 localhost、§4.7；15 §4.3 |
| U9 | AI 模型输出与云端返回 | `geode-ai` | 生成的模板被执行（≈U2）、提示注入破坏 Verifier 假定 | 03 §8 强制过 Verifier；03 §10 隐私分级 |
| U10 | 剪贴板内容 | 粘贴识别器 | 误识别致数据错位（可撤销）、超长粘贴撑爆内存 | 05 §4.6 识别序；04 §4.2 64MB 临时文件出口 |

**归类规则**：新增任何一种"能从外部进入本进程的字节流"必须在 §2.3 加一行，否则 PR 视为未完成（与 18 §12"数据修改路径必须写为什么安全"并列）。

## 3 数据结构与接口

> 本节内容 = **攻击面登记**：先给登记所需的类型契约（3.1，全部落在 `geode-core` 或 `geode-project` 的配置层），再给每个入口的登记表（3.2）与 P0 入口的逐条拆解（3.3）。

### 3.1 类型契约

```rust
pub struct ThreatId(pub u16);        // TH-01..TH-22，永不复用、永不删除
pub struct SurfaceId(pub u16);       // §3.2 表行号

pub enum ImpactClass { Rce, Leak, Corruption, DoS }   // 允许多个，取最高者为等级依据
pub enum Level { High, Medium, Low }

pub enum Boundary { Process, Ffi, Network, AiCloud }  // B1~B4

pub struct UntrustedInput {
    pub id: u8,                      // U1..U10
    pub surface: SurfaceId,          // 从哪个入口进入
    pub boundary: Boundary,          // 首次跨界点
    pub impact_if_failed: Vec<ImpactClass>,
    pub defense: Vec<DefenseId>,     // 引 §5 的 M1..M9
}

pub struct Threat {
    pub id: ThreatId,
    pub scene: &'static str,         // 一行场景，必须可被 20 转成语料
    pub impact: Vec<ImpactClass>,
    pub existing: Vec<DefenseRef>,   // (文档号, 节号)——指向已有防线
    pub residual: Vec<ResidualRisk>, // 残余风险，不得为空（空 = 假装解决了）
    pub level: Level,
}

/// 安全策略是"本机事实"，必须与项目文件解耦（§8、TH-14）。
pub struct SecurityPolicy {
    pub readonly_default: bool,          // 默认 true
    pub allow_unsigned_content: bool,    // 默认 false
    pub privacy_mode: PrivacyMode,       // 默认 Strict（§8 裁决）
    pub overridable_by_project: bool,    // 恒 false，不可配置
}
```

**三条类型级约束**（违反即设计缺陷，不只是实现缺陷）：① `ResidualRisk` 不得为空——"没有残余风险"是自我欺骗；② `SecurityPolicy` **不得**出现在 `.geoproj`/`.geopkg` 反序列化目标里（只能来自 `config.toml`）；③ `ImpactClass` 与 `Level` 的映射是纯函数，不允许各子系统自行再加一档。

### 3.2 攻击面登记（每个入口一行）

优先级：`P0` = 可致 RCE 或不可逆数据损坏；`P1` = 可致进程崩溃或数据可信度下降；`P2` = DoS 或体验级。

| # | 入口 | 现有防线（文档节） | 仍需补的防线 | 残余风险 | 优先级 |
|---|---|---|---|---|---|
| 1 | 打开本地文件（0~100GB） | pread + 页缓存，**不对可变文件 mmap**（04 A.1）；越界不 panic、短读合法（00 §5.1） | 打开期可选 `full_blake3`；`stat` 与首读窗口的尺寸一致性断言 | 解析期间文件被替换，只能发现不能避免 | P1 |
| 2 | 打开原始磁盘/分区 | 默认 `caps.writable=false`；六条二次确认；已挂载分区禁写（06 §4.4） | 每次写入的**审计日志**（现仅 toast）；快照目录 `0700` 校验 | 提权态确认后无撤销路径 | P0 |
| 3 | 附加进程内存 | `writable` 恒 false；holes 显式；ASLR 失配标 stale（06 §4.5） | PID 复用检测（`boot_id` + 启动时间） | 读到的是"另一个同名进程" | P2 |
| 4 | 远程数据源 | RSP 仅 localhost、`M` 默认不发、`allow_remote=false`（06 §4.6）；凭据走 keyring（17 §3.4.3） | SFTP 返回路径的二次规范化（TH-07）；host key 变更强制指纹比对 | 服务端本身不可信 | P1 |
| 5 | BinSpec 编译 | 源码 ≤512KB、嵌套 ≤512、`import` ≤8（15 §4.9）；`E4xxx` 精确诊断（02 §8.2） | **编译期内存配额**（现只有运行期 `Budget`） | 512KB 内仍可构造巨型 AST | P1 |
| 6 | BinSpec 执行 | `Budget{steps,wall_time,mem_vars,depth,output}`（02 §7.2）；取消延迟 <1µs | **全局**预算（多文档并发的合计配额） | 每文档 5s × N 文档打满 CPU | P1 |
| 7 | 数据处理器图 | `max_output` 4GiB + 1000:1 压缩比预警；合成深度 16（07 §4） | "拒绝启用"后不得残留半启用状态（需断言） | 1000:1 以下的慢速炸弹 | P1 |
| 8 | 可视化器（内置） | `image::Limits` + `w*h*4 ≤ 256MiB` + 帧数 256 + 输入 ≤64MiB + 2s watchdog（13 §6） | 递归容器（zip 内图片）的合并深度上限 | 编码器 0day | P1 |
| 9 | 可视化器（插件提供） | 同上 + `catch_unwind`（13 §6 `E8007`） | 插件自带解码器**必须**复用 `geode-viz` 的上限，不得自行 alloc | `plugin.mem_quota_mb` 统计不到插件内部 allocator | P1 |
| 10 | 搜索 | `regex::bytes` 线性时间；拒绝反向引用/环视；`max_match_len`（08 §4.3） | 用户正则的**长度上限**（现无） | `(?s).*` 在 100GB 上跑满预算 | P2 |
| 11 | Diff | 内存峰值 <800MB（09 §5） | 不可信源与可信源的页缓存隔离 | 大量小文件 diff 拖慢全局缓存 | P2 |
| 12 | 反汇编 | 每次 `decode_block` ≤64KiB；只用上游 fuzz 过的稳定版（11 §6） | 子进程隔离（v1 未做）；Capstone 版本 pin + 每日 `cargo-audit`（18 §6） | C 层段错误 = 进程直接死 | P0 |
| 13 | YARA 编译/扫描 | 双层护栏、禁 `include`、纯 Rust `yara-x`、200MiB、60s（12 §4.3/§6） | 规则来源（adhoc / 内容库 / 项目文件）的信任标签隔离 | `yara-x` 自身 0day | P1 |
| 14 | 插件加载 | 摘要 + 签名必需、子进程预检、`plugin.dirs` 前缀校验、ABI 版本检查（14 §3/§4.1） | macOS `disable-library-validation` 的显式风险提示（14 §4.1 已声明为妥协） | 掌握签名私钥者可分发 RCE | P0 |
| 15 | 插件调用 | 每个 ABI 入点 `catch_unwind`；5s 看门狗；连续 3 次失败禁用（14 §4.2/§6） | 无抢占能力（已诚实声明）；`mem_quota_mb` 不可强制的事实须写进用户文档 | 段错误/死循环 = 进程死 | P0 |
| 16 | 内容安装与更新 | 摘要 → 签名 → 解包（路径+配额）→ schema → 安装，顺序固定（15 §4.3）；装 ≠ 启用（§4.9） | 启动时对已装内容**抽查**重验摘要（现仅装时验一次） | 验过后磁盘上被替换 | P1 |
| 17 | 项目/工作区加载 | 路径一律相对 + 指纹校验 + `TooNew` 拒绝（17 §3.4/§4.2/§4.4） | `.geoproj` 的 `providers` 段**不得静默建立连接**（需显式同意） | 同事发来的文件可指向任意主机/路径 | P1 |
| 18 | journal 回放与恢复 | CRC + `base_*` 指纹 + 只回放 `EditOp`（17 §4.6/§9.2） | 回放路径 fuzz（20 承接）；`.trash` 保留期与权限 | 本地攻击者可伪造 journal 覆盖数据 | P2 |
| 19 | 主题与字体加载 | token 完备 `E0120`、等宽实测 `E0130`、热重载失败保留旧主题（16 §4.7） | 字体文件尺寸上限与 `FontData` 解析路径的配额 | 字体解析器 0day、显存耗尽 | P2 |
| 20 | AI 采样与云端调用 | 默认本地；`strict` 不发字节；发送前预览可逐片剔除（03 §10）；M5 验收含"抓包断言无出网" | provenance 的密钥脱敏；`permissive` 的**逐次**授权 | 用户开 `permissive` 后无二次拦截 | P0 |

## 4 核心算法流程

> 本节内容 = **一次不可信输入如何走完防线（4.1）** 与 **TH-01~TH-22 威胁清单（4.2）**。清单是流程的产出：每条 TH 都是某个入口在某一步防线缺失时的具体后果。

### 4.1 防线施加顺序（所有入口共用，不得跳步）

```
ingest(bytes, surface) ->
  ① 身份/来源：来自哪里？签名/指纹可信否？      // M2/M6，失败 -> EC001
  ② 形状拒绝：声明尺寸/条目数/嵌套深度 vs 上限   // 只拒绝，不分配      -> EC003
  ③ 预算登记：从用户设置取 steps/bytes/time/mem   // 不从输入取          -> EC007
  ④ 执行/解码：在 ③ 的预算内，边界 catch_unwind    // 段错误不可捕获（M9）
  ⑤ 产出校验：区间必须落在输入内（ByteRange::clamp），诊断必带 range
  ⑥ 落地：写盘/发网/给 UI —— 破坏性与外发型动作在此单列一次二次确认  // M3/M4
```

**不变量**：②之前在 ③之后不允许发生任何"按输入规模"的分配；③的数值来源必须是 `SecurityPolicy`/`config.toml`，出现"取输入里的长度做预算上界"即 `EC007`。这条流程与 02 §7.2、07 §4、12 §4.3、13 §6、15 §4.3 的具体实现是同构的，只是粒度不同——新增子系统时应直接套用而不要另发明一套。

### 4.2 TH-01 ~ TH-22 威胁清单

影响缩写：**RCE** / **泄露**（信息外泄）/ **损坏**（数据损坏或可信度被破坏）/ **DoS**。

| ID | 场景 | 影响 | 现有防线 | 残余风险 | 等级 |
|---|---|---|---|---|---|
| TH-01 | 恶意 `.bspec` 用不收敛循环，打开文件即挂死 UI | DoS | `Budget.steps=50M`/`wall_time=5s`（02 §7.2），超限 `E2001` 并保留部分结果；取消 <1µs | 多文档无合计配额；`#[budget]` 放宽后单模板可更长 | 中 |
| TH-02 | 模板用构造的偏移/长度做算术，溢出或读到 Buffer 之外 | 泄露/崩溃 | 全链 `Offset(u64)` + `checked_add`（04 A.2）；`ByteRange::clamp` 自动裁剪（00 §4）；`E3xxx` | transform 节点自算偏移处（07）仍需逐节点复核 | 中 |
| TH-03 | 编译期炸弹：512 层嵌套、深 `import` 链、巨型 AST 撑爆内存 | DoS | 源码 ≤512KB、嵌套 ≤512、`import` ≤8（15 §4.9）；编译 <20ms/1000 行（00 §7） | **编译期无独立内存配额**，只有静态阈值 | 中 |

| TH-05 | 图片解码炸弹：header 声明 60000×60000，分配即 OOM | DoS | `image::Limits` + `w*h*4 ≤ 256MiB` 自检 + 帧数 256 + 输入 ≤64MiB（13 §6）；`E8004` | 插件/第三方可视化器自带解码器可绕过全部四道 | 中 |

| TH-08 | 保存时目标被换成符号链接或并发替换，`rename` 覆盖了别的文件 | 损坏 | 解析真实路径、在真实父目录建 temp；temp 用 `O_EXCL\|O_NOFOLLOW` + 128 位随机（04 A.3） | 检查与 `rename` 之间仍有窗口 | 高 |
| TH-09 | mmap 期间文件被外部 `truncate`，访问越界页触发 `SIGBUS` | 崩溃 | **主防线：不对用户可变文件 mmap**，一律 pread（04 A.1）；`SIGBUS` handler 只做标记 + `_exit(70)` | 映射自身只读文件仍有理论窗口 | 低 |
| TH-10 | Capstone 在畸形字节流上段错误，`catch_unwind` 抓不到 | 崩溃 | 单次 `decode_block` ≤64KiB；只用上游 fuzz 过的稳定版；崩溃后靠 journal 恢复（11 §6） | C 层 UB 不可恢复；子进程隔离是 v2 | 中 |
| TH-11 | YARA 规则集病态：10 万条规则、`(a+)+$` 正则、`include /etc/passwd` | DoS | 编译/扫描双层护栏、禁 `include`、单规则 ≤2s、整包 ≤10s、扫描 60s/200MiB（12 §4.3/§6） | `yara-x` 内部缺陷；`per_rule_timeout` 依赖引擎支持 | 中 |
| TH-12 | 插件 panic / 段错误 / 死循环 / 越界写，宿主同进程 | 崩溃/RCE | 每个 ABI 入点 `catch_unwind`、5s 看门狗、子进程预检、连续 3 次禁用（14 §4.2/§4.4） | **段错误与死循环必然杀死应用**（14 §7.3 已声明）；`catch_unwind` 拦不住 UB | 高 |

## 5 性能预算与基准

> 本节内容 = **防线机制库（5.1，九条）**、三条铁律（5.2）与**这些防线自身的开销预算（5.3）**。防线不是免费的：验签、子进程预检、静态检查都在关键路径上，必须有数字，且不得突破 00 §7。

### 5.1 九条机制

| # | 机制 | 硬性要求 | 落点 | 可测断言 |
|---|---|---|---|---|
| M1 | **预算与配额** | 一切"按输入规模执行的工作"必须有 `steps`/`bytes`/`time`/`mem` 四维上限，上限值来自**用户设置**而非输入；触顶必须返回部分结果 + 可定位诊断 | 02 §7.2、07 §4、12 §4.3、13 §6 | 构造 100× 输入，耗时与内存不超配额；取消响应 <100ms |
| M2 | **路径规范化 + 白名单根** | 外部路径先 `canonicalize` 再断言前缀 ∈ 白名单根；解包场景额外拒绝 `..`、绝对路径、盘符、`\0`、symlink、段数 >8、总长 >1024 | 15 §4.9、14 §8、17 §4.2 | `../` 语料 100% 拒绝；三平台各一份语料 |
| M3 | **只读默认** | 危险源 `caps.writable == false`；写能力是独立开关且**按会话**生效，不记忆 | 06 §4.4/§4.5 | 首次写入必弹确认（自动化断言，不可跳过） |
| M4 | **破坏性操作二次确认** | 要求输入目标标识（设备名/PID/主机）而非点"确定"；按钮冻结 ≥500ms；系统盘/EFI 三次确认；**否决"记住上次"** | 06 §4.4 | 脚本化点"确定"无法通过；每条确认分支有回归用例 |
| M5 | **权限最小化** | 需特权的 open 先 `drop_privileges` 再访问；不发起提权（不 `sudo`、不 UAC）；所需 entitlement 逐项列明并对外声明 | 06 §4.4、14 §4.1 | 打开设备后 `getuid() != 0`；entitlement 清单进发布检查 |
| M6 | **大小上限 + 三段式校验** | **声明 → 上限 → 分配**：元数据里声明的尺寸只用于**拒绝**，绝不用作 `with_capacity`/`alloc`；边解边计数，不信 `uncompressed_size` | 13 §6、07 §4、15 §4.9 | 谎报 header 的样本不触发分配（分配器计数器断言） |
| M7 | **禁止 include 与网络** | `.bspec` 无 `include`、无网络；YARA 禁 `include`；`BspecFn` 必须 `purity=pure` 且无 I/O；插件侧 `plugin.network` 恒拒绝 | 12 §4.3、14 §3.3、02 §7.1 | 静态扫描 + 运行期断言双查；禁止 crate 中出现 `std::net` 即 CI 红灯 |
| M8 | **诊断与日志脱敏** | `Secret` 的 `Debug` 恒 `REDACTED`、不实现 `Serialize`；日志不含文件内容（只含偏移与长度）；崩溃转储默认关闭，开启时 `0600` 且 UI 明示 | 06 §3.2、17 §9.4、14 §4.4 | 字节级 `grep` 0 命中；`Zeroizing` 的 `Debug` 有单测 |
| M9 | **崩溃隔离选项** | 现有：插件子进程预检、`catch_unwind` 边界、`SIGBUS` handler 只做 `_exit(70)`；远期：反汇编子进程、插件进程隔离（v2） | 14 §4.4、11 §10、04 A.1 | panic 类语料下宿主存活；段错误类记为"预期崩溃"并验证崩溃处理器产出正确插件名 |

### 5.2 三条铁律

- **铁律 A（默认拒绝）**：防线默认开启且默认拒绝。任何"可关闭"的防线必须同时有配置项（§8）、UI 常驻警示、一条"关闭后失去什么"的文案。没有警示的开关视为缺陷。
- **铁律 B（三问）**：新增"执行用户提供的逻辑"的功能（DSL 特性、脚本节点、插件能力、规则语法），PR 必须回答：① 预算是多少、在哪检查？② 上限值来自谁（用户设置 vs 输入）？③ 触顶后降级到什么可观测状态？三问答不全不合并。
- **铁律 C（不信声明）**：以"输入里声明的尺寸"直接决定分配的代码路径一律打回。审查时搜索 `with_capacity`、`vec![0;`、`alloc(`、`new_uninit_slice`，逐个确认参数来源。

### 5.3 防线自身的开销预算

| 防线动作 | 预算 | 条件 | 越界后果 |
|---|---|---|---|
| 内容包验签（哈希 + Ed25519） | < 50ms / 32MB 包 | 单核，不含下载 | 安装体验退化；**不允许**为提速而跳过验签 |
| 插件子进程预检 | ≤ 80ms/插件（超时 5s） | 14 §4.4 已给值 | 冷启动变慢；超时即不加载（宁可少一个插件） |
| 模板静态检查（嵌套/import/大小） | < 5ms/文件 | 编译前 | 计入 00 §7 的"编译 <20ms/1000 行"预算内 |
| 可视化器守卫（header 拒绝 + 自检） | O(1) | 分配前 | 不得为守卫引入二次解码 |
| 路径规范化（每次外部路径） | < 100µs | 含 `canonicalize`（可能触磁盘） | 热路径禁止逐块调用；只允许在"打开/安装"边界调用一次 |
| 日志脱敏 | 与日志量同阶 | 只做字段级替换，不做内容扫描 | 禁止对文件内容做正则脱敏（会把 100GB 读一遍） |

**总约束**：以上开销合计不得使 00 §7 的任一门槛（打开 <200ms、滚动 <16ms、编译 <20ms）失守；若冲突，**降级功能而不是降级防线**。

## 6 失败模式与降级

> 本节内容 = **防线失效时的表现与降级（6.1）** 与 **漏洞响应流程（6.2~6.4）**。"失败模式"在这里的含义是"某条防线被绕过/缺失时，系统退化成什么"——这是评估残余风险最小可接受程度的依据。

### 6.1 防线失效矩阵

| 失效 | 检测点 | 系统退化为 | 用户可见 | 不得发生 |
|---|---|---|---|---|
| 签名校验失败或缺失 | 15 §4.3 ③ | 该内容**不启用**，其它内容照用 | 红框"包已被篡改或签名不正确" `EA002/EA003` | **不得**降级为"警告后继续"（除用户显式放行单文件并记入信任列表） |
| 解包时发现穿越/超配额 | 15 §4.3 ④ | 整包拒装，staging 全删 | 指出具体 entry 名 `EA004/EA005` | **不得**"跳过坏 entry 继续装" |
| 模板触预算 | 02 §7.2 | 返回**已解析的部分结果** + `E2001` | 结构树展示部分 + 提示"卡在哪个循环第几次" | 不得丢弃全部结果；不得重试同一模板 |
| 解码触上限 | 13 §6 | 显示已解出部分 + 错误横幅 | `E8003/E8004` | 不得静默渲染空白 |
| 插件 panic | 14 §4.2 | 该调用返 `GEODE_ERR_INTERNAL`，插件标记 Suspect | 无（或一次性提示） | 不得让 panic 跨 ABI 边界 |
| 插件段错误/死循环 | 崩溃处理器 / 看门狗 | **应用死亡**（声明事实）；重启后定位可疑插件 | 下次启动弹"是否禁用插件 X" `E9009` | 不得声称可恢复；不得自动重载该插件 |
| Capstone 段错误 | — | 进程死亡；靠 journal 恢复至崩溃前编辑状态 | 重启后恢复提示（17 §4.7） | 不得尝试"捕获后续跑" |
| Provider 中途失效 | 06 §3.2 | 该文档转只读/冻结，其它文档照用 | 红条 + 错误码 | 不得让一个源拖垮全应用 |
| 内容源离线 | 15 §6 | 已装内容照用，不弹模态框 | 状态栏"内容库离线" | 不得阻塞启动 |
| 密钥后端不可用（headless） | 17 §3.4.3 | 拒绝需要凭据的功能（远程源/AI） | 说明与替代路径 | **不得**静默退化为明文文件存储 |
| 防线开关被用户关闭 | §8 | 该防线失效，其余不变 | 常驻警示条 | 不得在关闭状态下仍显示"已保护" |

### 6.2 失败处理的总原则

对齐 00 §9.3（降级优于失败）与 §9.4（默认安全），但加一条**优先级**：**安全防线的失败必须朝"更不可用"的方向退化**（拒绝加载、转只读、禁用插件），**而不是朝"更可用"的方向**（跳过校验、忽略错误继续）。这条与性能维度的"降级优于失败"方向相反，冲突时以安全为准。

### 6.3 漏洞响应（`SECURITY.md` 要点与流程）

`SECURITY.md` 放仓库根（随 18 §3.1 目录约定），必备 7 条：① 支持窗口 = 当前 stable 的两个 minor 分支 + 最新补丁；② 私密渠道 = `security@<domain>` 别名 + GitHub Private Vulnerability Reporting，**不接受公开 issue**；③ 发布 PGP 公钥指纹（私钥离线），并说明不加密也可受理；④ 我们需要的材料（受影响版本、平台、最小复现或生成脚本、影响类别、是否已公开）；⑤ 我们**不会**做的（不代用户清理主机、无赏金、不受理无 PoC 的纯理论报告——例外是可指认具体代码路径的越界/UB）；⑥ 安全港声明（善意研究不追责，不要拿他人数据测试）；⑦ 披露政策与历史公告归档位置。

| 阶段 | 承诺 |
|---|---|
| 首次回音 | ≤3 个工作日（自动回复 + 人工确认收到） |
| 初判定级 | ≤10 个工作日（回复等级与理由） |
| 修复 | **90 天**内发补丁；`高` 等级目标 **30 天** |
| 协同披露 | 90 天到期公开；双方可书面延期一次（≤30 天）；若已在野利用立即缩短至补丁可用时 |

### 6.4 CVE、公告与可复现构建

- 满足任一即申请 CVE：跨信任边界的 RCE/越界写、可被远程输入触发的崩溃（U1/U4/U8）、凭据泄露、不可撤销的数据损坏。**纯 DoS 与界面问题不发 CVE**，进 CHANGELOG。
- 公告模板要素（缺一不发布）：① 受影响区间与修复版本；② 影响类别 + CVSS 向量与我们的评分理由；③ **触发条件**（"需要打开恶意文件"必须写明，这是用户评估风险的唯一依据）；④ 临时缓解措施；⑤ 致谢（可匿名）；⑥ 时间线；⑦ 需用户手动操作的事项（清缓存、轮换密钥、重装内容）；⑧ CVE 号与 commit 链接。
- 补丁分支：修复先进 `main`，再 cherry-pick 到两个支持分支各自打 tag；安全修复合并前不公开（私有 fork 或临时私有分支）。
- **可复现构建**：`Cargo.lock` 入库、`SOURCE_DATE_EPOCH` 固定、发布产物由 CI 从 tag 构建并附 `SHA256SUMS` + 签名；`cargo-audit` 每日跑（CRITICAL 当日修、HIGH 一周内，18 §6）+ `cargo-deny` 许可证与来源检查。用户可用同一 tag 本地重建并比对哈希——**这是"补丁真的修了"唯一可验证的形式**。

### 7.4 错误码段 `ECxxx`（已登记入 00 §12）

安全策略类诊断独占 `ECxxx` 段；`EBxxx` 归自有文件格式解析与迁移（见 23 §6、24 §6.1），两段不得混用。

| 码 | 语义 | 触发点 |
|---|---|---|
| `EC001` | 安全策略拒绝（需用户显式放行） | 未签名内容、被吊销密钥、`allow_unsigned=false` |
| `EC002` | 路径越出白名单根或被判为不安全条目 | M2 全部检查点 |
| `EC003` | 输入声明的尺寸/数量超上限（**拒绝**，非失败） | M6 三段式校验第二段 |
| `EC004` | 破坏性操作缺少二次确认（程序性错误，仅内部） | M4 |
| `EC005` | 将在写出物中发现凭据类字段 | 17 §4.10 导出自检 |
| `EC006` | 远程目标未经用户同意（`providers` 段静默连网） | TH-14 |
| `EC007` | 预算/配额由**输入**而非用户设置提供（程序性错误） | M1、铁律 C |

## 8 配置项与默认值

| 键 | 默认 | 为什么默认这样 | 打开后失去什么 |
|---|---|---|---|
| `security.open_readonly_default` | `true` | 打开陌生文件的第一动作不该是"可写"（00 §9.4） | 可直接编辑保存；一次误操作即污染样本 |
| `providers.disk.write_enabled` | `false`（**不记忆**） | 块设备写入不可撤销（TH-19） | 每次会话首次写都要重走六条确认 |
| `providers.proc.write_enabled` | `false`（UI 置灰） | 写他人进程内存是调试器行为，不是分析行为 | 可改目标进程状态，无审计兜底 |
| `providers.gdb.allow_remote` | `false` | RSP 无认证无加密（TH-20） | 明文传输、任意主机可连 |
| `content.allow_unsigned` | `false` | 供应链是最高杠杆攻击面（TH-16） | 任何能写内容目录的进程都可植入模板/插件 |
| `content.auto_apply_template` | `false` | 打开文件即执行模板 = 打开文件即执行代码（TH-01 放大器） | 恶意文件可自动触发模板解析 |
| `content.auto_install_updates` | `false` | 更新 = 自动引入新代码 | 后台静默替换已审内容 |
| `plugin.require_signature` | `true` | 插件 = 任意代码（TH-13） | 无可追溯来源的代码进入地址空间 |
| `plugin.preflight_subprocess` | `true` | 挡掉"装载即崩"与"ABI 不符"两类高发问题（14 §4.4） | 加载期崩溃率上升；省 80ms/插件 |
| `plugin.network` | **不可配置，恒拒绝** | ABI 不提供即无从绕过（M7） | —（不存在打开的路径） |
| `ai.privacy_mode` | **`strict`** | 取证数据的默认去向必须是"不出本机"（TH-15）。**注**：03 §10 现文写 `balanced` 为默认，与本文冲突，按本文裁决为 `strict`，03 需回填 | 失去"只发采样切片"的便利，本地小模型准确率低一档 |
| `ai.cloud_upload_max_bytes` | `65536` | 硬约束"不发整文件"（03 §10） | 单次外发上限提高 |
| `ai.provenance_record` | `true` | 可审计、可复现（03 §10） | 无法追问"模板是哪个模型在哪份样本上生成的" |
| `crash.dump_enabled` | `false` | minidump 含缓存页，可能带出文件内容（TH-18） | 崩溃归因变难；开启时目录强制 `0600` 且 UI 明示 |
| `log.include_content` | `false` | 日志进 issue 就进公网 | 排障变难（只给偏移与长度） |
| `search.regex_max_pattern_len` | `1024` | 用户正则无长度上限时可拖死 100GB 扫描（§3.2 #10） | 超长模式不可用（改 `within_node` 组合） |
| `magic.library_paths` | 内置 + `~/.config/geode/magic/` | 只信任本地与已验签内容（TH-17） | 更多未审规则进入"打开即匹配"路径 |
| `security.overridable_by_project` | `false`（**不可配**） | 一个 `.geoproj` 不应能降低你的安全姿态（§10 Q4） | —（硬编码，无开启路径） |

**使用规则**：新增任何 `security.*` 或破坏性开关，必须在本文加一行（含"打开后失去什么"），否则视为未完成；建议 `cargo xtask docs`（18 §4）扩展一条检查：`security.` 前缀键必须出现在 19 §8。
