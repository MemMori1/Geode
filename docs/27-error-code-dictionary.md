# 27 错误码字典

> **本文拥有**：127 个诊断码的段位归属、严重级、一句话释义、触发条件、可执行动作与正文出处的集中登记，以及 `docs/errors.toml` 的释义覆盖率账本。
> **本文不拥有**：码的语义本身（由 00 §12 与各段主文档拥有，本表只引用）；上屏文案的组装规则（25 §3.4、16 §4.6）。
> 上游：`docs/errors.toml`（机读登记，`cargo xtask docs-errors` 的唯一事实源）、00 §12；下游：`crates/geode-core/src/error_codes.rs`（生成物）、各分册错误表。

## 0 速览

**127 码、13 段、125 条可上屏、2 条待补**（EA101/EA106）。三条铁律：码只查表不猜语义；`Diag.message` 只进日志；每条「用户该做什么」都必须是能点的动作。

### 0.1 怎么用这个表

三步，不要跳：

1. **产码**：代码里只放 `Code` 常量与机器消息——`Diag::error(error_codes::E3002, "resume target outside file")`。消息是英文、稳定、可 grep 的，**不翻译**。
2. **查表**：用码在本文对应段位表里取三样东西：一句话释义（what）、触发条件（why）、可执行动作（fix）。运行时等价物是 `CopyTable`（`dsl.err.<CODE>.{short,long,action}`，22 §4.7）。
3. **上屏**：由 `UiText` 按码组装文案，`CopyTable::compose` 把三段拼成「发生了什么 / 为什么 / 怎么办」+ 动作按钮。

```rust
// ① 产码：只带码与机器消息（进日志）
return Err(Diag::error(error_codes::E1004, format!("magic mismatch at {off:#x}")));

// ② 上屏：按码查表，三段式组装（25 §3.4）
let t = UiText::from_code(error_codes::E1004).with_arg("off", off);
copy.compose(&t, &tr);   // what / why / fix + 动作按钮
```

两条铁律：

- **`Diag.message` 只进日志**：它是给开发者 grep 的机器消息，不拼用户可见句子，也不做 i18n。任何把 `message` 直接塞进弹窗的写法都是 bug（25 §3.4）。
- **上屏文案只由 `UiText` 组装**：同一码在 hex 面板、通知中心、CLI 三处必须同一套 what/why/fix，差异只在呈现形态（16 §4.6）。

兜底：码不在表里时 `CopyTable::compose` 回退 `err.unknown` 并 `tracing::warn!`；`CopyTable::coverage()` 是 CI 门禁，缺失率必须为 0（允许 `待补` 占位，但不允许静默回退）。

### 0.2 一页账本

| 指标 | 值 | 说明 |
|---|---|---|
| 登记码数 | 127 | 13 个段位，与 `errors.toml` 逐条一致 |
| 严重级 | error 110 / warning 15 / info 2 | 逐码复核，依据见各段正文 |
| 可上屏释义 | 125 | 三段式齐全，可直接落 `dsl.err.*` |
| 待补占位 | 2 | EA101、EA106，仅以区间出现，见 §4.1 |
| 无正文出处 | 2 | 上项同两条，未编造语义 |

标记说明：码后的 **†** 表示语义存疑（§7 有对应开放问题）；**‡** 表示 owner/段位登记与实际产码 crate 不一致；**•** 表示无正文出处。无标记即三方（正文、`errors.toml`、本表）一致。

### 0.3 三条使用纪律

- **先定段再找码**：段位决定谁的锅。E0 是工具链、E1~E5 是 BinSpec、E6 是数据源、E7 是搜索、E8 是可视化、E9 是插件、EA 是内容、EB 是格式/迁移、EC 是安全。跨段猜码一定猜错。
- **触发条件是判据，不是建议**：同一码在不同调用点的触发条件必须一致；不一致说明产码点选错了码，改码不改表。
- **动作必须能落地**：本表不写「检查权限」，只写「以管理员权限重试」「换一个输出路径」「导出已读部分」。写不出具体动作，说明这个码的降级路径还没设计好。

## 1 目标与非目标

| 编号 | 目标 | 验收方式 |
|---|---|---|
| G1 | 单点查表：127 码一页可查，不必翻 13 份分册 | 任取一码，30 秒内在本表定位到释义、触发、动作、出处 |
| G2 | 文案可生成：每码三段式可直接落 `dsl.err.<CODE>.*` | `CopyTable::coverage()` 为 100%，无 `err.unknown` 回退 |
| G3 | 覆盖可审计：空释义、无出处、owner 漂移都有账 | §4 清单与 `errors.toml` 统计一致 |
| G4 | 变更可门禁：增删码必须三处同步 | `cargo xtask docs-errors --check` 双向通过 |

非目标：

- **N1 不定义语义**。码的含义由 00 §12 与各段主文档拥有；本表只做索引与归一，冲突时以正文为准（§6）。
- **N2 不替代 22 §4.7**。机器消息（英文）与参数占位符仍由 22 维护，本表只给中文底稿。
- **N3 不做翻译**。本表是 zh-CN 底稿，i18n key 由 16 §4.6 规定，译文不进仓库主分支。
- **N4 不制定 severity 策略**。本表登记现值与正文依据；「该不该升级」是评审问题，见 §7 Q8。

## 5 维护规则

### 5.1 新增一个码：三处同步，缺一即红

1. **`docs/errors.toml`**：加条目，`id/segment/owner/severity/title` 全填；`title` 是生成 rustdoc 的输入，不许空着提交。
2. **本表**：在对应段位表加一行；「出处」必须指向真正解释该码的正文小节（不是 `errors.toml` 行号）。
3. **正文**：在该段主文档写出触发条件与降级路径，至少一句；只写码不写上下文不算。

### 5.2 双向门禁的准确语义

```bash
cargo run -q -p xtask -- docs-errors --check
```

它会同时检查两个方向，任一方向失败即退出非零：

- **文档有、表里没有**：`docs/**/*.md` 里出现的码未登记进 `errors.toml` → 失败（防止「正文先写、登记后补」漏掉）。
- **表里有、文档没提**：`errors.toml` 登记的码在所有文档里都搜不到 → 失败（防止「登记了但没人解释」）。

因此不能靠删本表行来消码，也不能靠正文随手写个码来补登记。**已知盲区**：本表 126 行本身也算「文档提到」，所以工具只验证「存在性」，不验证「解释质量」。评审时必须抽查「出处」列，确认引用的正文真的解释了这个码——这是人工门禁，不是工具门禁。

### 5.3 其余四条

- **不许复用码**：已发布（v0.1 起）的码只增不改；语义变了就发新码，旧码标废弃，不复用编号。
- **改 title 必须重跑生成器**：`error_codes.rs` 的 rustdoc 由 title 渲染，改完先跑不带 `--check` 的 `cargo run -q -p xtask -- docs-errors`，再跑 `--check`，否则 rustdoc 漂移。
- **空 title 只降不升**：允许暂时留空，但必须进 §4 清单且不得编造；「缺释义」计数在本表 §0.2 记账，只许降。
- **severity 双写一致**：本表与 `errors.toml` 的严重级必须逐条一致；改级要同改两处，并在 PR 里引用正文依据。
