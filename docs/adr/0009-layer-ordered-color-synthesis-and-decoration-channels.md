# 0009 — 高亮合成用层级定色 + 装饰通道

## 状态

已接受（2026-11-08）

## 背景

一屏 ~4000 单元格上可同时叠 10 类标注（Value/Search/Structure/Analysis/Selection/Bookmark/Diff/Yara/Ai/Cursor，见 00 §5.3），同一单元格常见 3~5 层叠加。合成必须在 16ms 帧预算内完成（960 cell 重算 < 0.8ms），且前景对比度须 ≥ **4.5:1**（`ratio = (L1+0.05)/(L2+0.05)`，`L = 0.2126R+0.7152G+0.0722B`，先 sRGB 线性化）。alpha 叠加会让"半透明色叠半透明色"的中间色不可预测、不可逆推，也无法保证对比度下限——用户在 5 层叠加处根本看不出这格是什么。色盲用户还需要每层有一个非色相通道。见 05 §4.7。

## 决策

高亮合成固定为**层级定色 + 装饰通道**：z 序即 Layer 枚举序、同层按 priority 再按 `AnnId`；底色取不透明层，其余层沿 HSL 压暗，装饰走独立像素通道。

- 底色：从最高 z 向下找第一个 `bg.a == 255` 的层作为 base；base 之下仍有 bg 的层**不做 alpha 混合**，而是沿 HSL 压暗 `l -= 0.05 × 层序差`（累计上限 0.20）；`opacity < 1` 时向默认底色插值。
- 装饰（不占底色）：下划线 1px（Search）、左带 3px（Yara）、顶边 1px（Diff）、斜纹（Ai 低置信），各占固定像素位置，互不覆盖。
- 前景：取最高 z 层的颜色，若与底色对比度 < `min_contrast` 则沿 L 轴二分修正（≤ 8 次）。

## 后果

**好处**
- 结果确定且可预测：同一组标注在任何缩放下都得到同一组颜色，用户能建立"这类颜色=这类含义"的稳定心智。
- 对比度有硬保证（≥ 4.5:1），暗底/亮底主题都成立，且不必为每层各调一套色。
- 装饰通道让"同时是高亮命中又是 YARA 命中"这类交叠不再靠颜色深浅区分，色盲友好（`colorblind_safe=true` 切 Okabe-Ito 8 色板）成为可选而非重做。
- 缓存键 (version, ann_epoch, theme_epoch, sel_epoch, cfg_hash) 使重算局部化。

**代价**
- 层序即语义，图层的枚举顺序成为 ABI 级的约定，插层要考虑兼容性。
- 压暗上限 0.20 意味着叠 5 层以后视觉差异趋近饱和，深层叠加的可辨识度靠装饰通道补。
- 结构深度用同色相亮度阶梯（L 62%→28%，步 6%）只有约 6 档可辨。

**待澄清**
- 05 §4.7 的 z 序只列了 **9 层**（缺 `Analysis`），与 00 §5.3 的 **10 个变体**不一致；`Analysis` 标注应插在 `Structure` 之后还是并入 Structure 语族，原文未写，需作者确认后本 ADR 才能定稿为稳定约定。

**何时应重新考虑**
- 若引入用户自定义配色或"标注可任意排序"，固定层序的前提消失。
- 若显示器进入 HDR/广色域，HSL 压暗与 4.5:1 的线性化假设要重算。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 直接 alpha 叠加 | 多层半透明叠出脏色，结果随叠放次序不可预测，对比度无法保证（见 05 §4.7） |
| 按 priority 加权混色 | 混合结果不可预测、不可解释，用户无法从颜色反推是哪类标注 |
| 永远固定深色前景 | 深色背景下不可读；对比度修正不可能（见 05 §4.7） |
| 只靠色相区分全部层 | 色盲用户不可用；层数一多色相不够分（需 Okabe-Ito 8 色上限） |
