# 0012 — diff 先滚动哈希锚点，再分段 Myers/Patience

## 状态

已接受（2026-11-08）

## 背景

目标：两个 **100MB** 文件在 **5s** 内出结果，内存峰值 < **800MB**（见 00 §7）。纯 Myers 是 O(ND)：两个 100MB 文件若有大量不同，D 可达 10⁸，直接不可用。而真实场景里绝大多数字节是相同的，差异是局部的；并且"头部插入 1 字节"这种偏移平移会让任何**块对齐**的比对方案全线失配（每块都对不上，且需要 O(N²) 试偏移）。锚点表规模可控：100MB / 64B ≈ 1.6M 条目 × 16B ≈ 26MB。

## 决策

三阶段：①滚动哈希找锚点（weak=adler-32 可滚动 + strong=xxh3_64，右文件**逐字节滚动**扫描并双向扩展）；②只在缺口上做有界细化（≤ 16KiB 用线性空间 Myers、≤ 64KiB 用 Patience/Histogram、> 64KiB 或预算耗尽整段标 Replace）；③用 Replace 段两侧 ≥ 16 字节公共前后缀做微调。

## 后果

**好处**
- 总复杂度 O(N) + 有界非线性项，实测 < 500ms 量级，5s 预算有大量余量。
- 偏移平移天然解决：逐字节滚动在头部插入 1 字节后于第 2 个字节命中，随后双向扩展出整段 Equal。
- 退化有界：完全不同文件缺口 > 64KiB ⇒ 整段 Replace 瞬间返回；全零文件被 `max_key_occ = 32` 的低信息块过滤剔除；长段重复靠"一个左块只能被消费一次 + 取最长 run"。
- `max_total_refine_bytes = 32MiB` 给细化预算上了硬顶，杜绝 Myers 在"细节过多的宽缺口"上退化。

**代价**
- 三阶段加二次确认（xxh3）的实现复杂度远高于单算法；并行化（左表按 8MB 超块并行、右滚动按片并行、合并时按 `r_off` 排序去重叠）也是额外工作量。
- 缺口 > 64KiB 时只有块级精度（整段 Replace），需要靠阶段三的公共前后缀与 UI 的"逐块展开"缓解。
- 参数（block_size 默认 32，可 16/64/128/256~1024；`max_key_occ = 32`）需按真实样本调，调错会掉锚点或表爆炸。

**待澄清**
- 09 §10 Q3 将"bsdiff 风格近似匹配 + delta 编码"列为倾向 v2 的开放项，未说明它与 PatchSet 导出的接口边界；若 v2 引入，需先明确 delta 是否复用阶段一的锚点表。

**何时应重新考虑**
- 若产品需要**可分发补丁**（不只是给人看差异），bsdiff 式 delta 编码的价值回升，需重新排序（见 09 §10 Q3）。
- 若结构级 diff（按 BinSpec 字段对齐）成为主视图，字节级流水线需重排顺序而非替换。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 纯全量 Myers（O(ND)） | 两个 100MB 大量不同时 D 可达 10⁸，远超 5s 与 800MB 预算 |
| 块对齐扫描 + 偏移差修正 | 插入/删除后块边界永久错位，每块都对不上，且需 O(N²) 试偏移（见 09 §4.1） |
| bsdiff 式 delta 编码（v1） | 对"人看差异"价值低，主要价值在可分发补丁；与 PatchSet 导出解耦后留待 v2（见 09 §10 Q3） |
| 无预算递归细化 | Myers 在缺口内退化失控，是"< 5s"预算的主要威胁；故设 `max_total_refine_bytes = 32MiB` |
| 只做结构级 diff | 字节级仍是事实来源，结构级只能叠加而不能替代（见 09 §10） |
