# 0013 — 插件用 C ABI + 声明式控件树

## 状态

已接受（2026-11-08）

## 背景

硬约束：除 `geode-ui`/`app` 外任何 crate 不得依赖 GUI 库（见 00 §2、18 §3.2），而 `geode-plugin-host` 位于 `geode-ui` **之下**。因此插件**无法引用 egui**，但插件又必须有 UI（面板、表格、按钮）。ABI 必须跨编译器与跨 Rust 版本稳定（G2：1.8x 编译的插件能被 1.9x 宿主加载），且 `.geoplug` 是 cdylib。egui 的 `Ui` 面有约 200 个方法、30 余个类型，且 minor 版本常带 breaking change。

## 决策

v1 采用 **C ABI + 版本化 vtable + 声明式控件树**：插件只提交控件树描述与数据，由宿主渲染并把事件回调给插件。

- 控件枚举 `GeodeWidgetKind { LABEL, VALUE, BUTTON, CHECKBOX, SLIDER, TEXT, TABLE, IMAGE, COMBO }`。
- 事件 `GeodeUiEvent { plugin_id, widget_id, kind, value }` 经 `CommandVTable::on_ui_event` 回调。
- 加载用 `RTLD_LOCAL`；Windows 用绝对路径 + `LOAD_WITH_ALTERED_SEARCH_PATH`；**永不真正 `dlclose`**，热重载 = 以新文件名加载新版 → 切换引用 → 旧版退役。

## 后果

**好处**
- 插件完全不接触 GUI 类型，分层不破，插件 ABI 与 egui 版本解耦：宿主升级 egui 不触发插件全量重编译。
- 声明式控件树覆盖约 **90%** 的真实需求（面板/表格/按钮/滑块/图片/文本），且宿主可统一施加主题、i18n、无障碍与 DPI 缩放。
- `struct_size` 前向兼容机制让 ABI 可以增字段而不破坏旧插件。
- 永不 `dlclose` 规避了 cdylib 卸载时跑 TLS 析构/`at_exit`、以及 rayon 线程仍持有返回地址导致的崩溃。

**代价**
- 需要自由绘制（自定义图表、自绘 hex 视图）的插件无法实现；这是明确的 v1 功能边界。
- 控件树每次重绘都要跨 FFI 编组，热路径（每秒 60 帧的复杂表格）需谨慎设计缓冲复用。
- 宿主承担了全部渲染与交互语义，控件种类的扩展必须走 ABI 而不是插件自带实现。

**何时应重新考虑**
- **量化触发条件**：若"需要自由绘制"的插件占比 > 20%，启动方案 B（egui 版本锁定通道 + C shim）与 A 并存，v1.1 落地。
- v2 上**独立进程 + 共享内存 + 插件自有窗口**做进程隔离（崩溃与越权隔离的价值那时才压过成本）。
- 若 WASM 沙箱成为安全要求，替换 cdylib 加载路径。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| B：宿主导出 egui 的 C shim，插件同版本编译 | ①约 200 个方法/30 余类型的 shim 本身就是需版本化维护的 ABI；②egui minor 常带 breaking change，"同版本编译"等于宿主升级 egui 就全量重编译插件，生态被版本锁死，同进程两个 egui 版本还会符号冲突；③成本 0.5 人月首次 + 0.3 人月/年，而"插件突然加载失败"的支持成本更高（见 14 §1.3） |
| C：v1 就上独立进程 + 共享内存 | 进程边界带来共享内存协议、生命周期、调试、跨平台 IPC 的成本，v1 收益不足；留待 v2 |
| D：插件链接 `geode-ui` | 分层崩塌，等于取消 L2/L3 边界，且让插件与 UI 内部类型永久耦合；永不采用 |
| 让插件自带窗口（不管渲染） | 多 viewport 已知的焦点回传/DPI/IME 问题（见 16 §4.1），且插件窗口不受宿主主题与 i18n 管辖 |
