# 0011 — 搜索默认在 Source 空间

## 状态

已接受（2026-11-08）

## 背景

搜索空间定义为 `SearchSpace { Source, Display { graph, view } }`（见 08 §3.4）。默认值决定了一大批下游语义：`Ann.range` 必须是 Buffer 偏移（C3），否则高亮、跳转、导出、patch 全要二次映射；而数据处理器图不一定保长（解压类无双射、位平面提取会重排），映射可能非单调甚至不存在。性能上 hex 搜索需 > 800MB/s、通配符 > 200MB/s、正则 > 80MB/s，且全流式单趟、不做索引（见 00 §7、08 §1）。

## 决策

搜索默认在 **Source 空间**（搜 Buffer 的字节，含 patch 后的状态），Display 空间为需显式满足条件的可选范围。

## 后果

**好处**
- 命中天然就是 Buffer 偏移，直接满足 C3，高亮/跳转/导出/patch 无需映射表。
- 不依赖图的保长与可逆性质，解压类、重排类视图不会产生"搜不到/搜到错位"的静默错误。
- 符合用户直觉与既有工具习惯（010 Editor、ImHex 默认搜源数据）。
- Display 的启用条件可机器判定：`caps.len_preserving && 单调可逆 OffsetMap && caps.deterministic`，不满足则菜单置灰而非报错。

**代价**
- 用户在看一个"解压后视图"时搜不到视图里的内容，需要先切范围；因此必须有不可关闭的常驻提示（搜索框下 12px 灰字："搜索范围：源数据（不含数据处理器视图）"）。
- Display 命中映射回源后若不连续，须标 `NonContiguous` 并对长区间做 `SearchEllipsis` 裁剪（> 4KiB 只标前 256B + 末 64B）。
- 结果绑 `base_version`，编辑后过期标 `Stale`，不自动重跑（`auto_rerun` 时防抖 500ms 且仅 scope ≤ 64MiB）。

**待澄清**
- 07 §7 的契约表写"搜索默认在视图上搜（否决默认在源上搜）"，与 08 §3.4 的"默认 Source"直接冲突。本 ADR 采纳 08 的裁决（08 是搜索子系统的自有文档、且给出 C3 与可逆性两条论证）；07 §7 表格需作者更正，或明确其"视图"指的是 hex 视图显示的内容而非 SearchSpace。

**何时应重新考虑**
- 若 Display 空间成为主要工作模式（如大量解压型分析），默认值与常驻提示的位置需要重估。
- 若实现出可靠的"任意图反向映射"（含非保长），Display 作为默认才可能成立。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 默认 Display 空间 | 违反 C3（命中须为 Buffer 偏移）；图不保长时映射不存在；用户直觉与竞品默认都是搜源数据 |
| 记忆上次选择作为默认 | 与"默认只读、不记住上次写入选择"同源的立场：隐式状态让同一操作在不同会话行为不同（见 06 §1.3 精神） |
| 两个空间都跑并合并结果 | 结果语义混杂（同一区间两套坐标），高亮与跳转无法统一；性能翻倍 |
| 只支持 Source，不提供 Display | 数据处理器视图是核心能力，完全禁用搜索会逼用户绕过工具 |
