# 25 — 用户体验流程与文案

> 本文只定义三件事：**用户走哪条路**（旅程与状态机）、**屏幕上有什么**（区域级线框）、**用户读到什么话**（文案结构与规范）。视觉与像素级布局归 `16-ui-shell-theme-i18n` 与主题 token，视图内部算法归 05/07/08/09，错误码全量人话映射归 22。
> 本文是可执行规格：§4.1 的六条旅程与 §9 的脚本一一对应。实现与本文冲突时，先改本文再改代码。

## 0 决策速览

## 1 目标与非目标

**目标**：G1 每条旅程可被外部脚本回放，断言点是「可见文本 + 可用命令」，不依赖截图比对；G2 每个可失败点都有三段式文案、至少一个出口动作、一个非模态兜底（`00 §9` 降级优于失败）；G3 空态、过渡态、降级态、只读态、冲突态、恢复态均有画面与出口，不存在「什么都没有」的界面；G4 文案结构化（key + 参数 + 严重度 + 可操作性 + 诊断码），可被 lint 与伪本地化门禁覆盖（`16 §4.6`）；G5 纯键盘可完成全部旅程，触控目标与对比度、色盲可辨有量化下限（§6）。

**非目标**：不做视觉设计与像素级布局规范（间距、圆角、字重、色值归 16 §3.1 与主题 token）；不定义分析引擎算法与内部预算（05/07/08/09 已定）；不维护错误码→人话全表（本文只给 25 条跨段样例，全表由 22 与 i18n 资源承担）；不写教程、营销文案与社区规范，不写人格化语气（拟人、幽默、颜文字、感叹号）；不做多窗口与可分离面板的流程（`16 §10` 已推迟）。

## 3 数据结构与接口

### 3.1 `UiText`：界面上的一段话

```rust
// TextKey = i18n key，命名空间见 16 §4.6；所有占位符见 args
pub struct UiText {
    pub key: TextKey,
    pub args: SmallVec<[(&'static str, TextValue); 4]>,   // 格式化白名单：hex|dec|size|pct|time
    pub severity: Severity,            // 复用 00 §4 的 Error|Warning|Info
    pub actionable: bool,              // 无出口动作的 Error 不允许上屏（lint 拦截）
    pub code: Option<DiagCode>,        // 有码必须能在 CopyTable 查到
    pub range: Option<ByteRange>,      // 有范围必须提供「跳到该偏移」
    pub actions: SmallVec<[UiAction; 3]>,
}
pub struct UiAction { pub id: ActionId, pub label_key: TextKey, pub kind: ActionKind, pub destructive: bool }
pub enum ActionKind { FocusOffset(Offset), Retry, SwitchReadOnly, SaveAs, ReloadFromDisk, ExportPatch, OpenSettings(&'static str), TrustKey(&'static str), Dismiss }
```

`args` 只允许占位符替换，禁止拼接句子片段（§8.1）；`severity` 与 `Diag.severity` 不一致视为实现缺陷。

### 3.2 查表接口：错误码 → 人话

```rust
pub trait CopyTable {
    fn entry(&self, code: DiagCode) -> Option<&CopyEntry>;
    fn compose(&self, t: &UiText, tr: &Translator<'_>) -> Option<Rendered>;  // 三段式组装，UI 唯一入口
    fn coverage(&self) -> Coverage;   // 已登记码数 / 缺文案码列表 → CI 门禁
}
pub struct CopyEntry { what_key, why_key, fix_key: TextKey, severity: Severity, default_action: Option<ActionKind> }
pub struct Rendered { headline: String, body: String, actions: Vec<(ActionId, String)> }
```

`Diag.message` 只用于日志与诊断导出，**不复用为界面文案**（它不参与翻译与 lint，`16 §4.6`）。

## 4 核心算法流程

### 4.1 六条核心旅程

每条给六个断面：触发 / 步骤 / 成功态 / 失败态 / 空态 / 感受；步骤里的界面文字即最终文案。
**J-A 打开 20GB 文件并滚到 90%**
- 触发：`file.open`（`Cmd+O`）/ 拖放 / 最近文件 / 命令行参数。
- 步骤：① 选文件 → ② `Loading`：`stat` 立刻给出 `SizeInfo::Known(20.0 GB)`，不读内容 → ③ 标签页 0ms 出现，hex 区 4 行骨架 + `正在打开 report.bin…` → ④ 首屏 64 KiB 上屏（≤200ms，`00 §7`）→ ⑤ 状态栏 `20.0 GB · 1,342,177,280 行 · 16 字节/行`，滚动条标「按行 / 按字节」比例尺 → ⑥ `Cmd+G` 输 `E0000000` 或拖 thumb 到 90%。
- 中间态「正在探测大小」：只对 `SizeInfo::Unknown` 的源（伪文件、SFTP、stdin）出现。文案 `正在探测大小… 已读到 1.2 GB（期间可以继续滚动）`；虚拟总长取 `max(len, len×1.25)`（`06 §4.2`），探测推进时**顶部偏移不动、只让 thumb 变短**；滚动条一端标 `≥ 1.2 GB（探测中）`，观测到 EOF 后换精确值并去掉 `≥`。用户看到的「文件多大」永远是区间而非假精确值。
- 成功态：目标行顶对齐并留 1 行上下文；状态栏偏移段 = 该行首字节；拖动期间浮层 `跳到 0xE0000000（89.9%）· 前 8 字节 · ZipArchive/localHeader`，松手后精绘。
- 失败态：权限拒绝 → `ReadOnly` + 黄条 `E6001`（§4.3）；文件不存在 → 回 `Empty` + 空态画面（线框 8）；块读取失败 → 该块斜纹 + 角标「不可读」，不弹模态（`05 §6`）。
- 空态：不适用（本旅程的产物就是「有文档」）。
- 感受：骨架 ≤300ms 必现；拖动浮层 ≤100ms 响应；滚动帧 ≤16ms；跳转精绘 <5ms。

**J-B 定位并覆盖编辑 3 个字节、撤销、保存（含冲突与恢复两支）**
- 触发：`Cmd+G` 跳转 / 点击单元格 / 命令面板 `nav.goto`；编辑直接键入（默认 Overwrite，`05 §3.3`）。
- 步骤：① 跳到 `0x1A3C` → ② 键入 `D E A D B E`：hex 列只接受 `0-9A-F`，其它字符红框脉冲 120ms 且不消费（`05 §4.6`）→ 3 字节覆盖合并为 1 个撤销单元 → ③ 状态栏 `已修改 · 补丁 13`，该行补丁底色 + 行首 `+` → ④ `Cmd+Z` 撤销（<1ms，无进度 UI）→ 补丁回落、行恢复 → ⑤ 重做或重新键入 → ⑥ `Cmd+S`。保存反馈分级：预检 <5ms 无 UI；写盘 >300ms 出进度条 + 取消；>2s 显示 `已写 1.2 GB / 20.0 GB`。
- 成功态：toast 3s `已保存 · 13 个补丁已写入文件`；脏标记清零；若保存期间继续编辑（`04 §4.6`）→ `已保存到版本 41，仍有未保存修改`。
- 失败态①（外部修改 → `Conflict`）：焦点回归或 5s 轮询命中（`04 §4.7`）→ 非模态横幅 `文件在磁盘上已被其它程序修改（修改时间 21:47）。` + `[重新载入] [保留我的修改] [另存为…]`；「保留我的修改」需二次确认并强制生成 `.bak`。
- 失败态②（崩溃恢复 → `Recovering`）：启动扫描到孤儿 journal（`17 §4.7`）→ 对话框 `上次异常退出，检测到 3 个未保存的修改`，每行 `文档名 | 编辑条数 | 时间范围 | 大小变化 | Clean/Partial`，可展开首尾各 20 条摘要 → `[全部恢复][选择恢复][查看详情…][丢弃…]`；强制恢复是独立路径、二次确认、成功后标签永久标黄；「丢弃」先移入 `journals/.trash/` 保留 7 天。
- 空态：无改动时 `file.save` 置灰并给 tooltip `没有需要保存的修改`（不隐藏命令，`16 §4.3`）。
- 感受：键入到上屏 ≤16ms；撤销 <1ms 且绝不出进度条；保存进度更新 ≥4Hz。

**J-C 四种搜索各一次并跳转（含「结果已过期」策略）**
- 触发：`Cmd+F` 开搜索条（四引擎 tab：hex / 文本 / 正则 / 数值）；`Cmd+Shift+F` 跨文档。
- 共同前置：搜索条下 12px 常驻灰字 `搜索范围：源数据（不含数据处理器视图）`（默认 Source，`08 §3.4`）。
- 步骤：① hex 通配 `4D 5A ?? ?? 03` → 首批 1000 条首帧可跳，其余 4096 条/帧上屏（`08 §3.5`）→ ② 文本 `MZ` 勾 UTF-8 / UTF-16LE / UTF-16BE → 列表按编码分组 `UTF-16LE 1,204 处` → ③ 正则 `\x50\x4B\x03\x04(?s).{0,64}?IHDR` 命中后跳转；写 `\1` 或 `(?=)` 时内联报 `E7103` 并给替代写法（不弹模态）→ ④ 数值 u32 ∈ `[0x1000, 0x2000]`、小端 → 结果附解码值列。跳转 = `Layer::Selection` + 当前命中加描边，`F3`/`Shift+F3` 循环。
- 成功态：结果面板头 `1,204 处命中 · 基于版本 41 · 3.2s · [导出]`；点击任意行即刻跳到该偏移。
- 失败态：全通配 → `E7102` 直接拒绝并解释；越上限 → `结果已截断（上限 100,000）`；内存不足 → 自动切 `CountOnly` `内存不足，仅显示数量`；`Display` 空间非连续命中灰显且不可跳转（`NonContiguous`）。
- 过期策略：任一编辑使版本 41→42 → 常驻黄条 `搜索结果已过期（基于版本 41，当前 42）— [重新搜索]`；列表整体降灰但**仍可点击**；**不自动重跑**（`08 §4.6`）；仅当范围 ≤64MiB 且 `ui.search.auto_rerun=true` 时 500ms 防抖静默重跑。
- 空态：`没有匹配。已搜索 20.0 GB · 用时 4.1s` + 三条排查建议（大小写、编码、是否该切 Display 空间）。
- 感受：输入防抖 200ms 后编译；≥300ms 显示扫描进度百分比；`Esc` 取消 → 保留已有结果、`complete=false`、不报错。

**J-D 用 BinSpec 解析（magic → AI 建议 → 置信三色 → 局部降级）**
- 触发：打开时 magic 命中 → 提示条 `检测到 ZIP（magic 库 common 2.3，置信 0.95）— [用 tpl.zip 解析]`（默认绝不自动跑，`15 §4.1`）；或 `Cmd+Shift+G` AI 猜结构（`Cmd+G` 是跳转，`16 §4.4`）。
- 步骤：① 0ms `正在分析…（可以继续滚动）` → ② ~300ms `已识别 3 个候选格式：ZIP / GZIP / TAR`（可点切换）→ ③ ~2s 本地 / ~6s 云端结构树流式长出，每闭合一个 `struct` 就上屏一段 → ④ hex 侧同步出现结构色带 + 左缘括号 → ⑤ 点树节点 → 最小滚动 `reveal_range` + 选中 + pinned 虚线（≤8 个）；点 hex → `deepest_at` 反向选中（`05 §4.8`）。
- 置信三色（必须叠加第二通道，§6）：深绿 `≥0.90` + 行尾 `✓`；黄 `0.50~0.89` + `≈`；灰 `<0.50` + `?`，且字段名强制显示 `unknown_0xNNNN`（不编造名字）。
- 局部降级：某字段失败（`E1004`/`E3001`）→ 仅该子树标红 + `Value::Unresolved`，父结构兄弟字段继续；该节点显示「数据不足」占位，hex 对应区间画红灰斜纹；**不整棵树失败**（`02 §P6`）。
- 成功态：根节点 `ZipArchive · 覆盖 100% 字节 · 4,213 字段`；右上 `[采纳] [编辑模板] [改置信度]`。失败态：预算耗尽 `E2001` → 保留部分结果 + 放宽预算入口；AI 超时 → 保留本地 magic 结果 + `AI 未在 20s 内返回，已显示本地识别结果`。
- 空态：`没有匹配的已知格式。[AI 猜结构] [手写模板] [浏览模板库]`（分别落到 AI 入口、模板编辑器、内容库）。
- 感受：300ms 必现候选；1s 内必现第一段结构；结构树与 hex 同帧联动不掉帧。

**J-E 两个文件 diff 并导出报告**
- 触发：`Cmd+Shift+D`；两侧 = 当前文档 + 选择的另一个文件（或其它已打开文档）。
- 步骤：① 选两侧 → ② 预检（大小、可 seek、指纹、模板一致性）→ ③ 若合计 >4GB 或预估 >30s：先提示 `两侧合计 8.0 GB，预计 55s，比对期间可以继续使用编辑器` + `[开始] [取消]` → ④ 进度（阶段名 + 百分比 + 取消）→ ⑤ 并排视图按对齐坐标系滚动 → ⑥ `F3`/`Shift+F3` 跳 hunk → ⑦ 导出（HTML / Markdown / CSV / `.geopatch`；预计 >50MB 时提示「建议导出 CSV」）。
- 成功态：`12 处差异（左 340 B / 右 352 B）· 4.6s · 精度：字节级`；两侧同步滚动，`Exact` 行对行，`InGap` 显示 `±N 字节偏差`。
- 失败态：内存峰值超预算 → 降块级精度并在计数旁常驻 `块级精度（1 块 = 64 字节）`（不许静默）；比对期间文件变化 → 自动重试 1 次后 `文件在比对期间持续变化，请关闭外部写入`；用户取消 → 丢弃半份结果并恢复原视图；模板不一致 → 禁用结构级 diff 并说明。
- 空态：两侧相同 → `两个文件完全相同（0 处差异）` + 两侧 blake3 前 16 位；一侧为空 → 1 个 Insert/Delete 直出。
- 感受：100MB×2 <5s；取消 p99 <100ms；并排取 60 行 <1ms。

**J-F 安装一个内容包（成功路径 → 签名失败 → 回滚）**
- 触发：内容库面板 / 双击 `.geopkg` / 详情页「安装」/ magic 提示条 `[安装 tpl.xxx]`。
- 成功路径：① 详情页 `tpl.zip 1.4.0 · 作者 @zipdev · 信任级别：作者签名（ed25519:9f2c3a11）· 1.4 MB · 无依赖` → ② 点「安装」→ ③ 进度分阶段并**显示阶段名**：`下载 42%` → `校验中：摘要 → 签名 → 解包 → schema` → `安装中` → ④ toast `已安装 tpl.zip 1.4.0`，详情页出现 `[立即用此模板打开当前文件] [回滚]`；若覆盖内置则 `已覆盖内置版本 v1.2.0`。
- 签名失败路径：① 停在「校验中：签名」→ ② 中止并删除 `.part` → ③ **模态**红框（安全事件，属少数允许模态的错误）：标题 `无法安装 tpl.zip 1.4.0`；正文「签名校验失败。文件摘要 `0c19…` 与索引登记不一致，包可能被篡改或在传输中损坏。已删除下载的临时文件，未修改任何已安装内容。」；按钮 `[重新下载] [查看详情…] [关闭]`。
- 密钥未知但签名有效（`EA003`）：`签名者 ed25519:deadbeef 不在受信列表`，默认按钮为 `[取消]`，`[仍要安装（风险自负）]` 需 `allow_unsigned` 二次确认；密钥已吊销时不提供该按钮。
- 撤销与回滚：`[回滚到 1.2.0]` → `已回滚到 1.2.0`（仅指针翻回，`15 §4.4`）；无可回滚版本 → `EA010 没有可回滚的版本，只能卸载`；卸载 → 自动回退内置 `已恢复内置版本 v1.2.0`；内置内容的「卸载」置灰，tooltip `内置内容只能被遮蔽，不能卸载`。
- 失败态（其它）与空态：zip slip / 解压炸弹 → 整包拒装 + 指出具体 entry；磁盘满 → `EA006` + 所需空间；依赖缺失 → 列出依赖 + `[仍然安装（功能受限）]`（装后标 `degraded`）；索引离线 → 状态栏 chip `内容库离线`，面板只显示已安装内容，**不弹框**（`15 §6`）。
- 感受：列表骨架 ≤300ms；下载进度 4Hz；校验阶段必须报阶段名，否则用户会以为卡死。
